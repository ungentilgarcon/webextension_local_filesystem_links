# Build from source

These instructions are for contributors and users who need to build the browser
add-on or native host themselves. The supported ready-to-install browser is
Firefox. Although a Chrome manifest is included in the source, the native-host
registration currently targets Firefox only; Chrome is not a supported setup.

## Build the Firefox add-on

Install Node.js/npm, then run these commands from the repository root:

```sh
npm install
npm run build
npm run bundle
```

The production extension is written to `dist/`; the installable ZIP is written
to `web-ext-artifacts/`. The Firefox ZIP can be installed in Firefox or
submitted to [Firefox Add-ons](https://addons.mozilla.org/en-US/developers/addon/local-filesystem-links/versions).

For development only, the Chrome manifest can be selected by setting
`BROWSER=chrome` when running the webpack build. This does not add Chrome native
messaging support, so local file links will not work end-to-end in Chrome.

## Build the Windows native host

Install 64-bit Python 3.15 and Inno Setup 6. During Python setup, enable
**Add Python to PATH**. From the repository root, install the native-host
dependencies and run its tests:

```powershell
py -3.15 -m pip install -r native-host\requirements.txt
py -3.15 -m unittest discover -s native-host\tests -v
```

Then build the host from `native-host/` using Git Bash (installed with Git for
Windows) and compile the installer from PowerShell:

```sh
cd native-host
sh build/build.sh
```

```powershell
& "${env:ProgramFiles(x86)}\Inno Setup 6\ISCC.exe" "native-host\build\windows\InnoSetupScript.iss"
```

The installer is written to `native-host/bin/win32/native-app-setup.exe`. It
registers the absolute host executable path for Firefox. Optional diagnostic
logging is disabled by default and can be enabled in the installer. If the
Python launcher or `pyinstaller` command is not found, rerun Python setup and
enable **Add Python to PATH**, then open a new terminal.

## Linux native host

The release workflow builds an x86-64 Debian package for Debian 12+ and Ubuntu
22.04+ systems with a system-installed Firefox. It installs the host and
native-messaging manifest system-wide for Firefox only; Snap and Flatpak
Firefox installations may not be able to access it. Chrome is not supported.
The current v0.2.17 release includes the package, which is available from the
[GitHub releases page](https://github.com/ungentilgarcon/webextension_local_filesystem_links/releases/latest).

The Linux build uses Python 3.15 and the PyInstaller version pinned in
`native-host/requirements.txt`. To build the `.deb` locally, use an x86-64 Debian 12+ or Ubuntu 22.04+ machine
with `dpkg-deb` installed. From the repository root:

```sh
python3.15 -m pip install -r native-host/requirements.txt
python3.15 -m unittest discover -s native-host/tests -v
(cd native-host && bash build/build.sh)
host_version="$(python3 -c 'import json; print(json.load(open("native-host/package.json"))["version"])')"
bash native-host/build/linux/package-deb.sh "$host_version" release-assets
```

This creates versioned and stable-name packages in `release-assets/`. Install
the package with `sudo apt install ./release-assets/local-filesystem-links-native-host.deb`.
To build the optional portable tar bundle instead, install Node.js/npm and run
the following from `native-host/`:

```sh
npm install
npm run build:unix
```

This creates `native-host/bin/linux/native-app-bundle-linux.tar`. To install it,
extract the archive into a directory that will remain in place and register the
native host for the current Firefox user:

```sh
mkdir -p "$HOME/local-filesystem-links-host"
tar -xf bin/linux/native-app-bundle-linux.tar -C "$HOME/local-filesystem-links-host"
cd "$HOME/local-filesystem-links-host"
chmod +x install_host_compiled.sh
./install_host_compiled.sh
```

Keep the extracted host files in place after installation: the registered
manifest points to the executable inside that directory. Restart Firefox after
installing. The installer writes the native-host manifest under the current
user's Mozilla configuration.

## Publish a Firefox add-on

Before submitting a new version, update the version in `package.json`, build
and bundle the extension, then upload the ZIP from `web-ext-artifacts/` to
[Firefox Add-ons](https://addons.mozilla.org/en-US/developers/addon/local-filesystem-links/versions).
Follow Mozilla's submission steps and provide the source archive generated by
`./make-sourcecode-archive.sh` when requested.

## Create a GitHub release

GitHub Actions builds the Windows installer and x86-64 Linux Debian package
when a version tag is pushed. It downloads the matching, already-published
Firefox add-on package from AMO, verifies its version, ID, and signature
metadata, then creates a **draft** release.

### Submit the Firefox add-on for public AMO listing

To submit a version for public discovery on Firefox Add-ons, run the separate
**Submit Firefox add-on to AMO** workflow from the repository's Actions page.
Enter the branch or commit containing the add-on version to submit. This uses
the `amo-metadata.json` listing details and includes a source archive. Mozilla
validates and reviews the submission; a successful upload does not mean the
listing is immediately approved or publicly visible. The GitHub release build
must wait until that exact add-on version is publicly available from AMO; it
does not submit or sign the add-on a second time.

This source build has a different Firefox add-on ID from the older AMO listing.
Submitting it creates or updates a separate listing and will not update the
older listing or automatically migrate its users.

### One-time repository setup

In the GitHub repository, open **Settings → Secrets and variables → Actions**
and add these repository secrets from the Firefox Add-ons API credentials:

-   `AMO_JWT_ISSUER`
-   `AMO_JWT_SECRET`

The AMO submission workflow requires these secrets. Do not put them in the
repository or in workflow files.

### Release steps

1. Update the extension version in the root `package.json` and the native-host
   version in `native-host/package.json`. The release tag must exactly match
   the native-host version, for example `v0.2.17`; the add-on version is
   recorded separately in the release notes and asset filename.
2. Update `CHANGELOG`, run the relevant builds/tests, commit, and push the
   release changes to `master`.
3. Submit the Firefox add-on using the **Submit Firefox add-on to AMO**
   workflow and wait until the exact version is public on AMO.
4. Create and push the version tag from that commit:

    ```sh
    git tag v0.2.17
    git push origin v0.2.17
    ```

5. In **Actions**, check that the published Firefox add-on, Windows installer,
   and Linux Debian package build jobs succeeded. The workflow creates a draft
   GitHub release with the publicly listed add-on and both operating-system
   native hosts, including versioned assets.
6. Review the generated release notes and download the assets from the draft
   to verify them. Then publish the draft in **Releases**.

Do not reuse a published tag. For another release, increment the native-host
version and create a new matching tag.

### Publishing through an authenticated corporate proxy

Git can use the current user's Windows integrated credentials to authenticate
to an NTLM/Kerberos proxy. Configure negotiation only for this repository, then
test the remote before pushing:

```powershell
git config --local http.proxyAuthMethod negotiate
git ls-remote origin HEAD
$tag = 'vX.Y.Z' # Replace with the new release tag.
git push origin master $tag
```

The proxy address still comes from the normal `HTTPS_PROXY`/`HTTP_PROXY`
environment settings. Do not put proxy usernames or passwords in Git config.
`Invoke-RestMethod` and `Invoke-WebRequest` can use the signed-in Windows
credentials explicitly:

```powershell
$proxy = 'http://proxyweb.villeurbanne.fr:3129'
Invoke-RestMethod `
    -Uri 'https://api.github.com/rate_limit' `
    -Proxy $proxy `
    -ProxyUseDefaultCredentials
```

If GitHub CLI reports `Proxy Authentication Required` or its saved token is
invalid, use GitHub's official CLI OAuth device flow through that authenticated
PowerShell proxy. The CLI's public OAuth client ID is
`178c6fc778ccc68e1d6a`. Request the `repo` scope for release management (add
`workflow` if dispatching Actions workflows). POST to
`https://github.com/login/device/code` with the client ID and scope, display the
returned `verification_uri` and `user_code`, then poll
`https://github.com/login/oauth/access_token` with the device code and
`urn:ietf:params:oauth:grant-type:device_code` grant until the user approves.
Send those requests with `-Proxy $proxy -ProxyUseDefaultCredentials`.

Start the device flow with:

```powershell
$oauthHeaders = @{ Accept = 'application/json' }
$clientId = '178c6fc778ccc68e1d6a'
$scope = 'repo' # Add ' workflow' if dispatching an Actions workflow.
$device = Invoke-RestMethod `
    -Method Post `
    -Uri 'https://github.com/login/device/code' `
    -Proxy $proxy `
    -ProxyUseDefaultCredentials `
    -ContentType 'application/x-www-form-urlencoded' `
    -Headers $oauthHeaders `
    -Body @{ client_id = $clientId; scope = $scope }

Write-Host "Open $($device.verification_uri) and enter $($device.user_code)"
Start-Process $device.verification_uri
```

After browser approval, poll the token endpoint until it returns `access_token`.
This loop observes GitHub's polling interval and device-code expiry:

```powershell
$pollInterval = [int]$device.interval
$expiresAt = (Get-Date).AddSeconds([int]$device.expires_in)
do {
    Start-Sleep -Seconds $pollInterval
    $tokenResponse = Invoke-RestMethod `
        -Method Post `
        -Uri 'https://github.com/login/oauth/access_token' `
        -Proxy $proxy `
        -ProxyUseDefaultCredentials `
        -ContentType 'application/x-www-form-urlencoded' `
        -Headers $oauthHeaders `
        -Body @{
            client_id = $clientId
            device_code = $device.device_code
            grant_type = 'urn:ietf:params:oauth:grant-type:device_code'
        }
    if ($tokenResponse.access_token) {
        break
    }
    switch ($tokenResponse.error) {
        'authorization_pending' { continue }
        'slow_down' { $pollInterval += 5 }
        'expired_token' { throw 'The device code expired; start a new flow.' }
        'access_denied' { throw 'Device authorization was denied.' }
        default { throw "Device flow failed: $($tokenResponse.error)" }
    }
} while ((Get-Date) -lt $expiresAt)
if (-not $tokenResponse.access_token) {
    throw 'The device code expired before authorization completed.'
}
$token = $tokenResponse.access_token
$headers = @{
    Accept = 'application/vnd.github+json'
    Authorization = "Bearer $token"
    'X-GitHub-Api-Version' = '2022-11-28'
}
```

Keep the returned access token only in the PowerShell process; do not paste it
into chat, command-line arguments, logs, or repository files. Use it as a
Bearer token in `Invoke-RestMethod` request headers. Verify
`GET https://api.github.com/user` returns `ungentilgarcon` before making
changes, and remove the token variable when finished.

GitHub may return 404 for a draft release at
`GET /repos/OWNER/REPO/releases/tags/TAG`, even when authenticated. Instead,
list drafts with `GET /repos/OWNER/REPO/releases?per_page=100` and select the
entry whose `tag_name` matches. Inspect `draft`, `assets`, and each asset's
`digest` before publishing. For AMO packages, compare the Firefox asset digest
with `current_version.file.hash` from the AMO API. Publish only the intended
draft by sending `PATCH /repos/OWNER/REPO/releases/RELEASE_ID` with
`{"draft":false,"prerelease":false,"make_latest":"true"}`. Verify the returned
release URL, draft state, and assets afterward.

Example for inspecting and publishing a verified draft after setting `$headers`
from the device-flow response above:

```powershell
$owner = 'ungentilgarcon'
$repo = 'webextension_local_filesystem_links'
$tag = 'vX.Y.Z' # Select the release you intend to publish.
$user = Invoke-RestMethod `
    -Uri 'https://api.github.com/user' `
    -Proxy $proxy `
    -ProxyUseDefaultCredentials `
    -Headers $headers
if ($user.login -ne $owner) {
    throw "Authenticated as unexpected GitHub account: $($user.login)"
}
$allReleases = Invoke-RestMethod `
    -Uri "https://api.github.com/repos/$owner/$repo/releases?per_page=100" `
    -Proxy $proxy `
    -ProxyUseDefaultCredentials `
    -Headers $headers
$release = $allReleases |
    Where-Object tag_name -eq $tag |
    Select-Object -First 1
if (-not $release -or -not $release.draft) {
    throw "Expected draft release $tag was not found."
}
$release.assets | Select-Object name, digest, size

$amo = Invoke-RestMethod `
    -Uri 'https://addons.mozilla.org/api/v5/addons/addon/local-filesystem-links-reboot/' `
    -Proxy $proxy `
    -ProxyUseDefaultCredentials
$amoHash = $amo.current_version.file.hash -replace '^sha256:', ''
$expectedDigest = "sha256:$amoHash"
$requiredAssets = @(
    'firefox-addon.xpi'
    "local_filesystem_links-$($amo.current_version.version).xpi"
    'native-app-setup.exe'
    "native-app-setup-$($tag.TrimStart('v')).exe"
    "local-filesystem-links-native-host_$($tag.TrimStart('v'))_amd64.deb"
    'local-filesystem-links-native-host.deb'
)
foreach ($name in $requiredAssets) {
    $asset = $release.assets | Where-Object name -eq $name | Select-Object -First 1
    if (-not $asset) {
        throw "Release is missing required asset: $name"
    }
    if ($name.EndsWith('.xpi') -and $asset.digest -ne $expectedDigest) {
        throw "Firefox asset digest does not match AMO: $name"
    }
}

$published = Invoke-RestMethod `
    -Method Patch `
    -Uri "https://api.github.com/repos/$owner/$repo/releases/$($release.id)" `
    -Proxy $proxy `
    -ProxyUseDefaultCredentials `
    -Headers $headers `
    -ContentType 'application/json' `
    -Body (@{ draft = $false; prerelease = $false; make_latest = 'true' } |
        ConvertTo-Json -Compress)
if ($published.draft) {
    throw "GitHub did not publish $tag."
}
$published.html_url
$headers.Clear()
$token = $null
$tokenResponse = $null
$device = $null
```

This method was used successfully to publish GitHub release `v0.2.17` through
the corporate proxy.
